The `@comark/email` package converts Markdown documents into responsive HTML that works in all major email clients. It uses [MJML](https://mjml.io) v5 to produce Outlook-safe, inline-styled output via native semantic email tags.

## Installation

::code-group

```bash [pnpm]
pnpm add @comark/email mjml
```

```bash [npm]
npm install @comark/email mjml
```

::

`mjml` is a required direct dependency. It is loaded lazily so the light transform path (`documentToMjml`) works without it.

## Frontmatter configuration

Control email metadata and theme via the `email:` key in your document frontmatter:

```markdown
---
email:
  subject: "Your order #1234 has shipped!"
  previewText: "Track your package delivery status."
  brandColor: "#0066cc"
  theme:
    background: "#f4f5f7"
---

# Document content here
```

| Key | Type | Description |
|-----|------|-------------|
| `subject` | `string` | Email subject line. Returned in `EmailRenderResult`. |
| `previewText` | `string` | Short preview shown in inbox before the body. Injected via `<mj-preview>`. |
| `brandColor` | `string` | Default button background color (`mj-button` via `mj-attributes`). Falls back to `theme.primary`. |
| `theme.background` | `string` | Background color applied to `<mj-body>`. |

## Render email HTML

`renderEmail` is the main entry point. It parses the Markdown, transforms it to an MJML JSON tree, compiles it with `mjml2html`, and returns `{ html, subject, previewText, errors }`.

```typescript
import { renderEmail } from '@comark/email'

const { html, subject, previewText, errors } = await renderEmail(`
---
email:
  subject: "Hello!"
  previewText: "Read this message."
  brandColor: "#0066cc"
---

# Hello

Welcome to Comark Email.

::email-button{href="https://example.com" background-color="#0066cc" color="#ffffff"}
Get Started
::
`)

// Pass output directly to your email provider
await sendEmail({ to: user.email, subject, html })
```

### Reusable renderer

Use `createEmailRenderer` when you need to render multiple documents with the same configuration. The underlying parser is initialized once.

```typescript
import { createEmailRenderer } from '@comark/email'

const render = createEmailRenderer({
  email: { brandColor: '#0066cc' },
})

const result = await render(markdownString)
```

### From a pre-parsed document

```typescript
import { parseMarkdown } from 'comark'
import { renderEmailFromDocument } from '@comark/email'

const doc = await parseMarkdown('---\nemail:\n  subject: Hello\n---\n# Hi')
const { html, subject } = await renderEmailFromDocument(doc)
```

### Debug: MJML XML string

Inspect the MJML tree without compiling to HTML:

```typescript
import { parseMarkdown } from 'comark'
import { documentToMjml } from '@comark/email'

const doc = await parseMarkdown('# Hello')
const xml = await documentToMjml(doc)
console.log(xml)
// <mjml>
//   <mj-head>...</mj-head>
//   <mj-body>
//     <mj-section><mj-column><mj-text ...>Hello</mj-text></mj-column></mj-section>
//   </mj-body>
// </mjml>
```

## Email components

The following built-in components are always active when using `renderEmail` or `renderEmailFromDocument`. They map to native MJML tags.

### `::email-button`

Renders an `<mj-button>` element. Pass MJML button attributes directly.

```markdown
::email-button{href="https://example.com/confirm" background-color="#0066cc" color="#ffffff" border-radius="4px"}
Confirm Email
::
```

Supported attributes:

| Attribute | Description |
|-----------|-------------|
| `href` | Link destination. Defaults to `#`. |
| `background-color` | Button fill color. |
| `color` | Text color. |
| `align` | `left` \| `center` \| `right`. |
| `border-radius` | e.g. `4px`. |
| `font-size` | e.g. `15px`. |
| `width` | e.g. `200px`. |
| `target` | e.g. `_blank`. |
| `padding` | e.g. `12px 24px`. |
| `class` | Mapped to `css-class` on the MJML tag. |

### `::email-columns`

Renders an `<mj-section>` with one `<mj-column>` per direct child block.

```markdown
::email-columns{background-color="#f9f9f9"}
**Left** column content.

**Right** column content.
::
```

Supported attributes: `background-color`, `padding`, `class` (→ `css-class`).

### `::email-divider`

Renders an `<mj-divider>`.

```markdown
::email-divider{border-color="#cccccc" border-width="1px" padding="16px 0"}
::
```

Supported attributes: `border-color`, `border-width`, `padding`, `class` (→ `css-class`).

## MJML compiler options

Forward options to the MJML compiler via `mjmlOptions`:

```typescript
await renderEmail(markdown, {
  mjmlOptions: {
    validationLevel: 'strict',
    beautify: true,
    minify: false,
  },
})
```

Available options: `validationLevel` (`strict` | `soft` | `skip`, default `soft`), `beautify`, `minify`, `fonts`, `keepComments`.

## Custom head CSS

Inject CSS into `<mj-style>` in the email head:

```typescript
await renderEmail(markdown, {
  headCss: 'a { color: #0066cc; }',
})
```

## Error handling

MJML compilation errors are collected into the `errors` array instead of thrown. The partial HTML is always returned.

```typescript
const { html, errors } = await renderEmail(markdown)

if (errors.length > 0) {
  console.error('MJML compilation errors:', errors)
}
```

## Plugins

All core Comark plugins are available via `@comark/email/plugins/*`:

```typescript
import { renderEmail } from '@comark/email'
import shiki from '@comark/email/plugins/shiki'
import math, { Math } from '@comark/email/plugins/math'
import binding, { Binding, If } from '@comark/email/plugins/binding'

const { html } = await renderEmail(markdown, {
  plugins: [shiki(), math()],
  components: { Math, Binding, If },
})
```
