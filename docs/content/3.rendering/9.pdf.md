The `@comark/pdf` package converts Markdown documents into PDF bytes using [jasy](https://jasy.dev). jasy is a declarative PDF renderer written in pure TypeScript — it maps the Comark AST directly to a jasy component tree and produces PDF bytes without a headless browser, HTML, or CSS.

## Installation

::code-group

```bash [pnpm]
pnpm add @comark/pdf
```

```bash [npm]
npm install @comark/pdf
```

::

No additional peers are required for basic use. `@jasy/pdf` is a direct dependency.

## Frontmatter configuration

Control page layout via the `pdf:` key in your document frontmatter:

```markdown
---
pdf:
  format: A4           # A4, Letter, A3, A5, etc.
  orientation: portrait  # portrait | landscape
  margin: 20mm         # shorthand, or { top, right, bottom, left }
  header: "My Report"  # center header; supports {{ page }} and {{ totalPages }}
  headerLeft: "Draft"
  headerRight: "Confidential"
  footer: "Page {{ page }} of {{ totalPages }}"
  footerLeft: "Company Name"
  footerRight: "2026"
---

# Document content here
```

## Render to PDF bytes

`renderPdf` is the main entry point. It returns a `Uint8Array` containing the PDF bytes.

```typescript
import { renderPdf, createPdfRenderer } from '@comark/pdf'
import { writeFile } from 'node:fs/promises'

// One-shot
const bytes = await renderPdf('# Hello\n\nWorld.')
await writeFile('output.pdf', bytes)

// Reusable renderer (parser initialized once)
const render = createPdfRenderer({
  pdf: { format: 'A4', margin: '20mm', footer: 'Page {{ page }} of {{ totalPages }}' },
})

const bytes = await render(markdownString)
```

### From a pre-parsed document

```typescript
import { parseMarkdown } from 'comark'
import { renderPdfFromDocument } from '@comark/pdf'

const doc = await parseMarkdown('---\npdf:\n  format: A4\n---\n# Hello')
const bytes = await renderPdfFromDocument(doc)
```

## Page breaks

Use the `::page-break` component to insert explicit page breaks.

```markdown
# Chapter 1

Content here.

::page-break
::

# Chapter 2

More content.
```

Supports `type="before"` for a break before the following element:

```markdown
::page-break{type="before"}
::
```

The `PageBreak` handler from `@comark/pdf/plugins/page-break` maps this to jasy's native `PageBreak()` component.

## Browser preview

Use `mount` from `@comark/pdf/preview` to render PDF bytes into an `<iframe>` via a Blob URL.

```typescript
import { renderPdf } from '@comark/pdf'
import { mount } from '@comark/pdf/preview'

const bytes = await renderPdf(markdownString)
const handle = mount(document.getElementById('preview'), bytes)

// Later, to free the Blob URL:
handle.revoke()
```

## Node PDF export

Use `renderPdfToBuffer` or `renderPdfToFile` from `@comark/pdf/node`.

```typescript
import { renderPdfToBuffer, renderPdfToFile } from '@comark/pdf/node'

// Write to file
await renderPdfToFile(markdown, 'output.pdf', {
  pdf: { format: 'A4', margin: '20mm', footer: 'Page {{ page }} of {{ totalPages }}' },
})

// Get a Uint8Array
const buffer = await renderPdfToBuffer(markdown)
```

## Feature support

`@comark/pdf` maps the Comark AST to jasy layout primitives. It does **not** run an HTML/CSS pipeline. Plugins that emit HTML, SVG, or DOM output cannot feed jasy directly. Those features are **degraded** for now: the source text is kept so the document still renders, but rich visual output is not produced.

| Status | Meaning |
|--------|---------|
| Supported | Maps to a native jasy component with full visual intent |
| Partial | Renders, but without the rich HTML/SVG visual (degraded) |
| Not yet | No dedicated mapper yet; falls through or shows a text placeholder |

### Markdown constructs

| Feature | Status | What you get | Why |
|---------|--------|--------------|-----|
| Headings (`h1`–`h6`) | Supported | Sized / bold `Text` by level | Direct jasy mapping |
| Paragraphs | Supported | `Paragraph` with word wrap | Direct jasy mapping |
| Bold / italic / strikethrough | Supported | Styled `span` runs | jasy `span` API |
| Inline code | Supported | Monospace `Courier` span | Direct jasy mapping |
| Links | Supported | Underlined blue span with `href` | jasy span navigation |
| Unordered / ordered lists | Supported | Bullet / number `Row`s in a `Column` | Direct jasy mapping |
| Nested lists | Partial | Nested columns; deep nesting may need polish | Layout is recursive; edge cases may iterate |
| Blockquotes | Supported | `Box` with left border | Direct jasy mapping |
| Horizontal rules | Supported | `Divider` | Direct jasy mapping |
| Tables | Supported | jasy `Table` with header row | Cell alignment from GFM attrs |
| Fenced / indented code blocks | Partial | Monospace `Text` in a tinted `Box` (no syntax colors) | Shiki emits HTML; jasy has no HTML intake |
| Images | Partial | Alt text placeholder (`[Image: …]`) | jasy `Image` needs a local path / bytes; remote URLs are not wired yet |
| HTML blocks / raw HTML | Not yet | Children may pass through as text, or be dropped | jasy is not an HTML renderer |
| Task lists | Partial | Rendered as list items; checkbox UI is not drawn | No checkbox primitive in the mapper yet |
| Footnotes | Partial | Body text may appear; dedicated footnote layout is not mapped | Needs a dedicated jasy layout |

### Page / PDF features

| Feature | Status | What you get | Why |
|---------|--------|--------------|-----|
| Page size / orientation / margins | Supported | jasy `Page` props from `pdf:` frontmatter or options | `pdfConfigToPageProps` |
| Headers / footers | Supported | Running header/footer with `{{ page }}` / `{{ totalPages }}` | jasy `PageNumber` / `PageCount` |
| Explicit `::page-break` | Supported | jasy `PageBreak()` (or `breakBefore` when `type="before"`) | Native jasy page break |
| Auto multi-page flow | Supported | Long content spills across pages | jasy pagination |
| Browser preview | Supported | PDF bytes in an `<iframe>` via Blob URL | `mount()` in `@comark/pdf/preview` |
| Node file / buffer export | Supported | `renderPdfToBuffer` / `renderPdfToFile` | Thin wrappers over `renderToBytes` |

### Plugins

Parser plugins still **parse** the markdown. The gap is in the **render** step to jasy.

| Plugin | Parse | Render | Status | What you get | Why / why not |
|--------|-------|--------|--------|--------------|---------------|
| `math` (KaTeX) | Yes | Degraded | Partial | LaTeX source as monospace text (inline) or in a tinted box (block) | KaTeX outputs HTML; jasy cannot consume HTML. Future: rasterize to an image and use jasy `Image`. |
| `mermaid` | Yes | Degraded | Partial | Diagram source as a monospace code block | `beautiful-mermaid` outputs SVG/HTML. Future: rasterize SVG → PNG and use jasy `Image`. |
| `shiki` / `highlight` / `rangi` | Yes (optional) | Degraded | Partial | Code is plain monospace; no theme colors or line highlights | Highlighters emit HTML/`<pre><code>` spans. The default `pre` mapper strips to plain text. |
| `binding` | Yes | Partial | Partial | Parser works; HTML `Binding`/`If` handlers are not provided for jasy | Conditional / interpolation need a jasy-specific component map |
| `alert` | Yes | Partial | Partial | Children render via generic passthrough; GitHub-style alert chrome is not drawn | No dedicated alert `Box` styles yet — override with a custom component |
| `emoji` | Yes | Supported* | Supported* | Shortcodes resolve at parse time to Unicode text | Text glyphs render if the font covers them |
| `toc` / `summary` / `frontmatter` / `components` / `attributes` | Yes | N/A | Supported (parse) | Affect the AST / meta; no separate visual chrome | Meta and structure only |
| `page-break` | Yes | Yes | Supported | See page features above | Dedicated jasy handler |

\* Emoji glyphs depend on the embedded / standard PDF font. Missing glyphs may be omitted.

### Why degrade instead of omit?

The recommended approach for this release is: **keep source text, drop rich HTML/SVG visuals**.

1. jasy builds PDF from a declarative component tree — not from HTML/CSS.
2. KaTeX, Mermaid, and Shiki were built for HTML (or SVG) renderers such as `@comark/html`.
3. Omitting nodes would lose author content. Degrading keeps the LaTeX / diagram / code source readable in the PDF.
4. Richer output can come later (for example: rasterize math/diagrams to images; map Shiki tokens to colored jasy `span`s).

### Plugins (usage)

Core parser plugins are available via `@comark/pdf/plugins/*`. For math and mermaid, register the degraded jasy components:

```typescript
import { renderPdf } from '@comark/pdf'
import math, { Math } from '@comark/pdf/plugins/math'
import mermaid, { Mermaid } from '@comark/pdf/plugins/mermaid'

const bytes = await renderPdf(markdown, {
  plugins: [math(), mermaid()],
  components: { Math, Mermaid },
})
```

Do not expect Shiki theme colors in PDF output. Code blocks always render as monospace text in a tinted box, with or without the shiki plugin.

## Custom components

Override any Comark component tag with a jasy component function:

```typescript
import { renderPdf } from '@comark/pdf'
import { Text, Box } from '@jasy/pdf'

const bytes = await renderPdf(markdown, {
  components: {
    alert: ([, attrs, ...children], ctx) =>
      Box({ bg: '#fff3cd', padding: 12, radius: 4 }, ctx.mapNodes(children)),
  },
})
```
