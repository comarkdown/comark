---
title: Renamed components
description: Comark's framework components were renamed to describe what they render. Old names and props still work as deprecated aliases.
---

Comark's framework components were renamed so that names describe **what they render** rather than the library they come from: you render *Markdown*, with Comark. The **Comark brand** is unchanged for package names (`comark`, `@comark/vue`, ...), parser APIs (`parse`, `renderMarkdown`, `autoCloseMarkdown`, ...), and `ComarkNode` / plugin types. AST container and element types were renamed to the `Markdown*` prefix (`MarkdownTree`, `MarkdownElement`, `MarkdownText`, `MarkdownComment`, `MarkdownElementAttributes`); the old `Comark*` names remain as deprecated aliases.

## Component names

| Old name | New name | Package |
|---|---|---|
| `Comark` | `Markdown` | `@comark/vue`, `@comark/react`, `@comark/svelte`, `@comark/nuxt` (auto-import) |
| `ComarkRenderer` | `MarkdownParsed` | `@comark/vue`, `@comark/react`, `@comark/svelte`, `@comark/nuxt` (auto-import) |
| `ComarkClient` | `MarkdownClient` | `@comark/react` |
| `ComarkLive` | `MarkdownLive` | `@comark/react` |
| `ComarkAsync` | `MarkdownAsync` | `@comark/svelte/async` |
| `ComarkNode` (component) | `MarkdownNode` | `@comark/svelte`, `@comark/angular` |
| `ComarkComponent` | `Markdown` | `@comark/angular` |
| `ComarkRendererComponent` | `MarkdownParsed` | `@comark/angular` |
| `defineComarkComponent` | `defineMarkdownComponent` | `@comark/vue`, `@comark/react`, `@comark/angular`, `@comark/nuxt` |
| `defineComarkRendererComponent` | `defineMarkdownParsedComponent` | `@comark/vue`, `@comark/react`, `@comark/angular`, `@comark/nuxt` |

The Angular selectors changed accordingly: `<comark>` → `<comark-markdown>`, `<comark-renderer>` → `<comark-markdown-parsed>`, and `<comark-node>` → `<comark-markdown-node>`.

## Prop names

| Old prop | New prop | Component |
|---|---|---|
| `markdown` | `value` | `Markdown` (and variants) |
| `tree` | `value` | `MarkdownParsed` |

All other props are unchanged (`components`, `plugins`, `options`, `streaming`, `caret`, `unwrap`, `data`, `comarkKey`, ...).

## Type names

| Old type | New type | Package |
|---|---|---|
| `ComarkTree` | `MarkdownTree` | `comark` (re-exported from framework packages) |
| `ComarkElement` | `MarkdownElement` | `comark` |
| `ComarkElementAttributes` | `MarkdownElementAttributes` | `comark` |
| `ComarkText` | `MarkdownText` | `comark` |
| `ComarkComment` | `MarkdownComment` | `comark` |

`ComarkNode` is unchanged.

```ts
// Before
import type { ComarkTree, ComarkElement, ComarkText } from 'comark'

// After
import type { MarkdownTree, MarkdownElement, MarkdownText } from 'comark'
```

## Backward compatibility

The old component names, props, and AST type names **still work** as deprecated aliases. Using a deprecated component or prop logs a one-time warning in the browser console during development to help you migrate. The old AST types (`ComarkTree`, `ComarkElement`, `ComarkText`, `ComarkComment`, `ComarkElementAttributes`) are type aliases of their `Markdown*` counterparts and remain exported with `@deprecated` JSDoc tags so editors surface the rename. The aliases will be removed in a future major version, so update your imports and templates when convenient.
