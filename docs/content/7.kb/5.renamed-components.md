---
title: Renamed components
description: Comark's framework components and AST types were renamed to describe what they represent. Old names still work as deprecated aliases.
---

Comark's framework components were renamed so that names describe **what they render** rather than the library they come from: you render *Markdown*, with Comark. The **Comark brand** is unchanged for package names (`comark`, `@comark/vue`, ...), parser APIs (`parse`, `renderMarkdown`, `autoCloseMarkdown`, ...), and plugin types (`ComarkPlugin`, ...).

## Component names

| Old name | New name | Package |
|---|---|---|
| `Comark` | `Markdown` | `@comark/vue`, `@comark/react`, `@comark/svelte`, `@comark/nuxt` (auto-import) |
| `ComarkRenderer` / `MarkdownParsed` | `MarkdownDocument` | `@comark/vue`, `@comark/react`, `@comark/svelte`, `@comark/nuxt` (auto-import) |
| `ComarkClient` | `MarkdownClient` | `@comark/react` |
| `ComarkLive` | `MarkdownLive` | `@comark/react` |
| `ComarkAsync` | `MarkdownAsync` | `@comark/svelte/async` |
| `ComarkNode` (component) | `MarkdownNode` | `@comark/svelte`, `@comark/angular` |
| `ComarkComponent` | `Markdown` | `@comark/angular` |
| `ComarkRendererComponent` | `MarkdownDocument` | `@comark/angular` |
| `defineComarkComponent` | `defineMarkdownComponent` | `@comark/vue`, `@comark/react`, `@comark/angular`, `@comark/nuxt` |
| `defineComarkRendererComponent` / `defineMarkdownParsedComponent` | `defineMarkdownDocumentComponent` | `@comark/vue`, `@comark/react`, `@comark/angular`, `@comark/nuxt` |

The Angular selectors changed accordingly:

| Old selector | New selector |
|---|---|
| `<comark>` | `<comark-markdown>` |
| `<comark-renderer>` / `<comark-markdown-parsed>` | `<comark-markdown-document>` |
| `<comark-node>` | `<comark-markdown-node>` |

## Prop names

| Old prop | New prop | Component |
|---|---|---|
| `markdown` | `value` | `Markdown` (and variants) |
| `tree` | `value` | `MarkdownDocument` |

`Markdown` also accepts a pre-parsed `MarkdownDocument` on `value` (not only a string). All other props are unchanged (`components`, `plugins`, `options`, `streaming`, `caret`, `unwrap`, `data`, `comarkKey`, ...).

::callout{icon="i-lucide-package" color="warning"}
Passing a tree/document to `<Markdown>` skips parsing at runtime, but the **parser is still bundled** because `Markdown` imports it. To keep the client bundle free of the parser, use [`MarkdownDocument`](/rendering/vue#code-markdowndocument) instead.
::

## Type names

| Old type (main) | New type | Package |
|---|---|---|
| `ComarkTree` | `MarkdownDocument` | `comark` |
| `ComarkElement` | `ElementNode` | `comark` |
| `ComarkElementAttributes` | `ElementNodeAttributes` | `comark` |
| `ComarkText` | `TextNode` | `comark` |
| `ComarkComment` | `CommentNode` | `comark` |
| `ComarkNode` | `Node` | `comark` |

```ts
// Before
import type { ComarkTree, ComarkElement, ComarkText, ComarkNode } from 'comark'

// After
import type { MarkdownDocument, ElementNode, TextNode, Node } from 'comark'
```

## Backward compatibility

Only names that existed on main are kept as deprecated aliases (for example `ComarkRenderer`, `MarkdownParsed`, `ComarkTree`, `ComarkElement`, `ComarkNode`). Using a deprecated component or prop logs a one-time warning in the browser console during development. Deprecated type aliases keep `@deprecated` JSDoc so editors surface the rename. These aliases will be removed in a future major version.
