Comark integrates with [Vite DevTools](https://devtools.vite.dev/) through the separate [`@comark/devtools`](https://github.com/comarkdown/comark-devtools) package. The panel is an interactive playground for real-time markdown editing and AST inspection, powered by [devframe](https://devfra.me/).

## Setup

Install the DevTools packages alongside `comark`:

::code-group

```bash [pnpm]
pnpm add -D @comark/devtools @vitejs/devtools
```

```bash [npm]
npm install -D @comark/devtools @vitejs/devtools
```

```bash [yarn]
yarn add -D @comark/devtools @vitejs/devtools
```

::

Add both plugins to your Vite config:

```ts [vite.config.ts]
import { defineConfig } from 'vite'
import { DevTools } from '@vitejs/devtools'
import comarkDevtools from '@comark/devtools/vite'

export default defineConfig({
  plugins: [
    DevTools(),
    comarkDevtools,
  ],
})
```

> [!TIP]
> If you use `@comark/vue`, its Vite plugin automatically includes `@comark/devtools` when that package is installed — no extra plugin entry needed:
> ```ts [vite.config.ts]
> import { defineConfig } from 'vite'
> import vue from '@vitejs/plugin-vue'
> import { DevTools } from '@vitejs/devtools'
> import comark from '@comark/vue/vite'
>
> export default defineConfig({
>   plugins: [vue(), DevTools(), comark()],
> })
> ```

### Live documents (optional host bridge)

When a `<Comark>` / `<ComarkRenderer>` is mounted with a `comarkKey` (or a tree with `meta.key`), the panel can list the live document and push edits back to the app. The Vite plugin injects the host bridge automatically; for manual setups you can connect yourself:

```ts
import { connectDevtools } from '@comark/devtools/host-client'
import { createComarkContext, parse } from 'comark'

connectDevtools(import.meta.hot)

const ctx = createComarkContext()
const doc = ctx.get('page', await parse('# Hello'))
```

```ts
// In the UI — same ambient context the host bridge mirrors:
// <ComarkRenderer :tree="tree" comark-key="page" />
// Panel edits call doc.set(newTree); the mounted renderer re-renders.
```

## Features

### Markdown Editor

The panel includes a markdown editor with [Shiki](https://shiki.style/)-powered syntax highlighting using the `mdc` grammar. Edits can be inspected as AST and, when a live instance is connected, pushed back to the running app.

### AST Tab

Displays the full parsed AST as syntax-highlighted JSON. Useful for understanding how Comark transforms your markdown and inspecting node structure.

### Push to App

When a live `<Comark>` instance is connected, edits in the devtools editor are pushed to the running application in real time. The plugin parses the markdown on the server and broadcasts the updated tree to the browser via HMR, where the framework renderer (Vue, React, Svelte, or Angular) re-renders with the new content.

Parse errors during editing (e.g. malformed frontmatter YAML) are caught gracefully — the previous tree is preserved so the editor never breaks mid-edit.

### Live Instance Connection

When a Comark component (`<Comark>` from `@comark/vue`, `@comark/react`, `@comark/svelte`, or `@comark/angular`) is mounted on the page with a context key, the DevTools panel automatically detects it.

## How It Works

| Layer | Module | Role |
|---|---|---|
| **Host bridge** | `@comark/devtools/host-client` (`connectDevtools`) | Browser-side bridge that mirrors `globalThis.comarkContext` over HMR |
| **Vite Plugin** | `@comark/devtools/vite` | Dev server plugin (devframe → Vite DevTools) that injects the host client and exposes RPC |
| **Devframe definition** | `@comark/devtools` | Portable UI/RPC definition — also usable with `createPluginFromDevframe` |

Framework renderers never talk to devtools directly. They only subscribe to the ambient context via `comarkKey` / `meta.key`. The host bridge lists keys, reverse-renders markdown for the panel, and applies panel edits via `doc.set`.

## Package

[`@comark/devtools`](https://github.com/comarkdown/comark-devtools) lives in its own repository and is versioned independently of `comark`. It depends on `comark` as a peer for parsing and markdown reverse-rendering.
