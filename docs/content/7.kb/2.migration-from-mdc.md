Comark replaces `@nuxtjs/mdc`. The Markdown and component syntax stays the same, so most `.md` files need no edits. This guide covers the JavaScript API changes, including package names, parse functions, the tuple AST, and plugins.

## Quick overview

- **Package**: `@nuxtjs/mdc` → `comark` (core) or `@comark/vue` (Vue renderer and Nuxt module)
- **Parse**: `parseMarkdown()`, and synchronous `createMarkdownParser()` (no `await`)
- **AST**: object tree → compact tuples `['tag', props, ...children]`
- **Result**: `result.body` and `result.data` → `document.nodes` and `document.frontmatter`
- **Renderer**: `<MDCRenderer :body :data>` → `<MarkdownDocument :value>`
- **All-in-one**: `<MDC :value>` → `<Markdown :value>`
- **Slots**: `<MDCSlot />` → native `<slot />`
- **Plugins**: global `nuxt.config` → per-component `defineMarkdownComponent({ plugins })`
- **Binding**: `{{ path }}` via opt-in [binding plugin](/plugins/built-in/binding) and render-time `data` prop (namespaced paths)
- **Markdown files**: component syntax unchanged; update binding paths if you used bare MDC names

## Package changes

If you only use the programmatic API (parse functions, plugins, AST utilities), install `comark`:

::code-group
```bash [npm]
npm uninstall @nuxtjs/mdc
npm install comark
```
```bash [pnpm]
pnpm remove @nuxtjs/mdc
pnpm add comark
```
```bash [yarn]
yarn remove @nuxtjs/mdc
yarn add comark
```
```bash [bun]
bun remove @nuxtjs/mdc
bun add comark
```
::

If you also use Vue components or the Nuxt module, install `@comark/vue` instead. It includes `comark` as a dependency:

::code-group
```bash [npm]
npm uninstall @nuxtjs/mdc

```
```bash [pnpm]

pnpm add @comark/vue
```
```bash [yarn]
yarn remove @nuxtjs/mdc
yarn add @comark/vue
```
```bash [bun]
bun remove @nuxtjs/mdc

```
::

## Core package

Every renderer builds on `comark`. These API changes apply whenever you call the parser in code, with or without Nuxt.

### Parse functions

#### One-shot parsing

::code-group
```typescript [Before]
import { parseMarkdown } from '@nuxtjs/mdc/runtime'
const result = await parseMarkdown(markdown)
```
```typescript [After]
import { parseMarkdown } from 'comark'
const document = await parseMarkdown(markdown)
```
::

#### Reusable parser

::code-group
```typescript [Before]
import { createMarkdownParser } from '@nuxtjs/mdc/runtime'
const parser = await createMarkdownParser(options)
const result = await parser(markdown)
```
```typescript [After]
import { createMarkdownParser } from 'comark'
const parse = createMarkdownParser(options) // synchronous, no await
const document = await parse(markdown)
```
::

`createMarkdownParser()` is synchronous and returns the parser right away. MDC's factory was async because it initialized a `unified` pipeline.

::tip{to="/reference/parse"}
See the Parse API for parser options and return types.
::

### Render functions

#### Serialize back to Markdown

::code-group
```typescript [Before]
import { stringifyMarkdown } from '@nuxtjs/mdc/runtime'
const markdown = stringifyMarkdown(result.body, result.data)
```
```typescript [After]
import { renderMarkdown } from 'comark/render'
const markdown = await renderMarkdown(document)
```
::

`renderMarkdown()` reads `document.frontmatter` and writes it as YAML frontmatter. See the [Render API](/reference/render) for options.

### Return type

The parsed document uses new field names:

::code-group
```typescript [Before]
// MDCParserResult
{
  body: MDCRoot        // the AST
  data: {              // frontmatter
    title: string
    description: string
    [key: string]: any
  }
  toc: Toc | undefined
  excerpt: MDCRoot | undefined
}
```
```typescript [After]
// MarkdownDocument
{
  nodes: Node[]                    // the AST
  frontmatter: Record<string, any> // frontmatter (all keys)
  meta: {
    toc?: Toc                      // requires toc plugin
    summary?: Node[]               // requires summary plugin
    [key: string]: any
  }
}
```
::

| MDC | Comark |
|-----|--------|
| `result.body` | `document.nodes` |
| `result.data` | `document.frontmatter` |
| `result.data.title` | `document.frontmatter.title` |
| `result.toc` | `document.meta.toc` (requires `toc` plugin) |
| `result.excerpt` | `document.meta.summary` (requires `summary` plugin) |

### AST format

MDC represents nodes as objects. Comark represents elements as tuples and text as plain strings:

::code-group
```typescript [Before]
// MDC object tree
{
  type: 'element',
  tag: 'p',
  props: { class: 'intro' },
  children: [
    { type: 'text', value: 'Hello world' }
  ]
}
```
```typescript [After]
// Comark tuple array
['p', { class: 'intro' }, 'Hello world']
//  tag   attributes        children...
```
::

Node checks and property access map as follows:

| MDC | Comark |
|-----|--------|
| `node.type === 'element'` | `Array.isArray(node)` |
| `node.type === 'text'` | `typeof node === 'string'` |
| `node.tag` | `node[0]` |
| `node.props` | `node[1]` |
| `node.children` | `node.slice(2)` |

Update custom AST walkers to use tuple indexing, or traverse documents with `visit()` from `comark/utils`.

::tip{to="/getting-started/document-model"}
See the document model guide for node types, parsed document structure, and traversal helpers.
::

### Plugins

MDC ran `remark` and `rehype` plugins on `unified`. Comark uses its own plugin interface and supports `markdown-it` parsing rules.

#### Syntax highlighting

::code-group
```typescript [Before]
import { createMarkdownParser, rehypeHighlight, createShikiHighlighter } from '@nuxtjs/mdc/runtime'

const parser = await createMarkdownParser({
  rehype: {
    plugins: {
      highlight: {
        instance: rehypeHighlight,
        options: {
          theme: 'material-theme-palenight',
          highlighter: createShikiHighlighter({ /* ... */ }),
        },
      },
    },
  },
})
```
```typescript [After]
import { createMarkdownParser } from 'comark'
import shiki from 'comark/plugins/shiki'
import githubLight from '@shikijs/themes/github-light'
import githubDark from '@shikijs/themes/github-dark'

const parse = createMarkdownParser({
  plugins: [
    shiki({
      themes: { light: githubLight, dark: githubDark }
    })
  ]
})
```
::

#### Table of contents

::code-group
```typescript [Before]
import { parseMarkdown } from '@nuxtjs/mdc/runtime'
const result = await parseMarkdown(md, { toc: { depth: 3 } })
const toc = result.toc
```
```typescript [After]
import { parseMarkdown } from 'comark'
import toc from 'comark/plugins/toc'

const document = await parseMarkdown(md, { plugins: [toc({ depth: 3 })] })
const tableOfContents = document.meta.toc
```
::

#### Excerpt and summary

::code-group
```typescript [Before]
const result = await parseMarkdown(md)
const excerpt = result.excerpt  // MDCRoot | undefined
```
```typescript [After]
import { parseMarkdown } from 'comark'
import summary from 'comark/plugins/summary'

const document = await parseMarkdown(md, { plugins: [summary()] })
const summaryNodes = document.meta.summary  // Node[] | undefined
```
::

#### Emoji

::code-group
```typescript [Before]
// enabled by default via remark-emoji
// mdc: { remarkPlugins: { 'remark-emoji': {} } }
```
```typescript [After]
import { parseMarkdown } from 'comark'
import emoji from 'comark/plugins/emoji'

const document = await parseMarkdown(md, { plugins: [emoji()] })
```
::

#### Binding (`{{ }}`)

MDC's built-in `{{ }}` syntax moves to the opt-in [binding plugin](/plugins/built-in/binding). See [Binding and data passing](#binding-and-data-passing) for namespaced paths and the render-time `data` prop.

```typescript
import { parseMarkdown } from 'comark'
import binding from 'comark/plugins/binding'

const document = await parseMarkdown(md, { plugins: [binding()] })
// Pass runtime data to the renderer, not to parseMarkdown()
```

### Parse options

::code-group
```typescript [Before]
// MDCOptions
{
  remark: { plugins: { /* record */ } },
  rehype: { options: {...}, plugins: { /* record */ } },
  highlight: { theme: '...', langs: [...] } | false,
  toc: { depth: 3, searchDepth: 2 } | false,
  keepComments: false,
  keepPosition: false,
}
```
```typescript [After]
// ParserOptions
{
  plugins: ComarkPlugin[],   // ordered array, not a record
  autoUnwrap: true,          // removes <p> from single-paragraph containers
  autoClose: true,           // completes unfinished syntax during streaming
  // linkify, frontmatter, html, alert, task-list, components, and attributes are on by default
}
```
::

The `mdc.config.ts` unified pipeline hooks (`pre`, `remark`, `rehype`, `post`) have no equivalent because Comark doesn't use `unified`. Use the `ComarkPlugin` interface instead.

::tip{to="/plugins"}
See the plugins guide for built-in plugins and custom plugin hooks.
::

## Nuxt module

### Configuration

::code-group
```typescript [Before]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mdc'],
  mdc: { highlight: { ... }, remarkPlugins: { ... } },
})
```
```typescript [After]
export default defineNuxtConfig({
  modules: ['@comark/vue'],
  // Configure plugins per component with defineMarkdownComponent()
})
```
::

`@comark/vue` auto-imports `Markdown`, `MarkdownDocument`, `defineMarkdownComponent`, `defineMarkdownDocumentComponent`, `parseMarkdown`, and `createMarkdownParser`. Plugin and component configuration moves out of `nuxt.config.ts` and into component definitions.

### Renderer component

::code-group
```vue [Before]
<MDCRenderer :body="result.body" :data="result.data" :components="components" />
```
```vue [After]
<MarkdownDocument :value="document" :components="components" />
```
::

Props that changed:

| MDC `<MDCRenderer>` | Comark `<MarkdownDocument>` | Notes |
|---|---|---|
| `body` (`MDCRoot`) | `value` (`MarkdownDocument`) | Takes the full `MarkdownDocument` (see [AST format](#ast-format)) |
| `data` (frontmatter) | Removed | Frontmatter lives on `document.frontmatter` |
| Not supported | `data` | Runtime values for [data binding](/syntax/components#data-binding) and [`{{ }}`](/plugins/built-in/binding), not frontmatter |
| `tag` | Removed | Wrapper is `<div class="comark-content">` |
| `prose` | Removed | `Prose*` component resolution is automatic |
| `unwrap` | `unwrap` prop or parse option | `<Markdown unwrap />` or `:options="{ unwrap: 'p' }"`. See [inline rendering](/reference/parse#inline-rendering) |
| `class` | Removed | Style the wrapper via CSS |
| `components` | `components` | Same purpose and shape |
| Not supported | `componentsManifest` | Async component resolver |
| Not supported | `streaming` | Streaming mode |
| Not supported | `effects` | Stream effects such as the blinking `caret()` from `comark/stream`. See [stream effects](/reference/reference#stream-effects) |

### All-in-one component

The `<MDC>` component maps to `<Markdown>`.

::code-group
```vue [Before]
<MDC :value="markdown" :parser-options="options" />
<MDC :value="result" />   <!-- pre-parsed MDCParserResult -->
```
```vue [After]
<Markdown :value="markdown" :options="options" />
<!-- or default slot -->
<Markdown>{{ markdown }}</Markdown>
```
::

For a pre-parsed document, use `<MarkdownDocument>` instead of passing it to `<Markdown>`.

::tip{to="/rendering/vue#nuxt"}
See Vue and Nuxt rendering for the component API, streaming setup, and SSR examples.
::

### `defineMarkdownComponent`

MDC configured plugins once in `nuxt.config.ts` for every parse call. In Comark, `defineMarkdownComponent()` and `defineMarkdownDocumentComponent()` create named components with their own plugins and component maps.

For example, an app can use one component with syntax highlighting, a table of contents, and emoji for articles, and a plain component for user comments:

```typescript [composables/markdown.ts]
import { defineMarkdownComponent, defineMarkdownDocumentComponent } from '@comark/vue'
import shiki from '@comark/vue/plugins/shiki'
import toc from '@comark/vue/plugins/toc'
import emoji from '@comark/vue/plugins/emoji'
import githubLight from '@shikijs/themes/github-light'
import githubDark from '@shikijs/themes/github-dark'
import CustomAlert from '~/components/Alert.vue'
import ProsePre from '~/components/ProsePre.vue'

export const ArticleMarkdown = defineMarkdownComponent({
  name: 'ArticleMarkdown',
  plugins: [
    shiki({ themes: { light: githubLight, dark: githubDark } }),
    toc({ depth: 3 }),
    emoji(),
  ],
  components: {
    alert: CustomAlert,
    ProsePre,
  },
})

export const CommentMarkdown = defineMarkdownComponent({
  name: 'CommentMarkdown',
})
```

```vue [pages/article/[slug].vue]
<script setup lang="ts">
import { ArticleMarkdown, CommentMarkdown } from '~/composables/markdown'
</script>

<template>
  <ArticleMarkdown>{{ article.content }}</ArticleMarkdown>
  <CommentMarkdown v-for="c in comments" :key="c.id">{{ c.body }}</CommentMarkdown>
</template>
```

The same pattern applies to `defineMarkdownDocumentComponent` when you pre-parse on the server:

```typescript [composables/markdown.ts]
export const ArticleMarkdownDocument = defineMarkdownDocumentComponent({
  name: 'ArticleMarkdownDocument',
  components: {
    alert: CustomAlert,
    ProsePre,
  },
})
```

```vue [pages/article/[slug].vue]
<script setup lang="ts">
import { ArticleMarkdownDocument } from '~/composables/markdown'

const { data: document } = await useFetch(`/api/article/${slug}`)
</script>

<template>
  <ArticleMarkdownDocument :value="document" />
</template>
```

### Slots in custom components

MDC required a special `<MDCSlot>` component inside your custom Vue components to render children. Comark uses the native Vue `<slot>` element instead.

#### Default slot

::code-group
```vue [Before]
<template>
  <div class="alert">
    <MDCSlot />
  </div>
</template>
```
```vue [After]
<template>
  <div class="alert">
    <slot />
  </div>
</template>
```
::

#### Unwrapping children

MDC's `<MDCSlot unwrap="p">` and the older `<slot mdc-unwrap="p">` attribute both map to `<slot unwrap="p">`:

::code-group
```vue [Before]
<!-- MDCSlot -->
<MDCSlot unwrap="p" />

<!-- older mdc-unwrap attribute -->
<slot mdc-unwrap="p" />
```
```vue [After]
<slot unwrap="p" />
```
::

The `unwrap` attribute strips the given wrapper tags from slot children, such as the `<p>` around single-paragraph slot content.

#### Named slots

Named slots work the same way as in MDC. Write `#header` in Markdown and `<slot name="header" />` in the Vue component:

```vue
<!-- components/Card.vue -->
<template>
  <div class="card">
    <div class="card-header">
      <slot name="header" />
    </div>
    <div class="card-body">
      <slot unwrap="p" />
    </div>
  </div>
</template>
```

```mdc
::card
#header
Card title

Body content here.
::
```

### Summary

In Vue, render only the summary with the `summary` prop:

::code-group
```vue [Before]
<MDCRenderer :body="result.excerpt ?? result.body" :data="result.data" />
```
```vue [After]
<Markdown summary>{{ markdown }}</Markdown>
```
::

### Prose components

Both MDC and Comark resolve `Prose*` components to override how standard HTML elements render. Unlike `@nuxtjs/mdc`, the Comark Nuxt module does not register `components/prose/` globally. Pass the components with the `components` prop or `defineMarkdownComponent()`, or register the directory in `nuxt.config.ts`:

```typescript [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@comark/vue'],
  components: [{ path: '~/components/prose', global: true, pathPrefix: false }, '~/components'],
})
```

Component names stay the same:

| Element | MDC component name | Comark component name |
|---------|--------------------|-----------------------|
| `<p>` | `ProseP` | `ProseP` |
| `<h1>` | `ProseH1` | `ProseH1` |
| `<a>` | `ProseA` | `ProseA` |
| `<pre>` | `ProsePre` | `ProsePre` |
| `<code>` | `ProseCode` | `ProseCode` |

Internally, MDC converted tags to kebab-case (`prose-p`) before looking up `ProseP`. Comark looks up `ProseP` in PascalCase directly. Existing `Prose*.vue` components work unchanged once you register them.

::note
Comark does not pass a `code` prop (or `meta.lines`) to `ProsePre`. Declare `__node` on your component and call `textContent()` from `comark/utils` to read the raw code for copy buttons or collapse thresholds. See [Custom code block](/kb/custom-code-block).
::

### Nuxt UI

If your project uses [Nuxt UI](https://ui.nuxt.com), the `@comark/vue` Nuxt module registers [Nuxt UI prose components](https://ui.nuxt.com/docs/typography) automatically.

[Nuxt UI](https://ui.nuxt.com) also provides callout shorthands for `::callout{icon="..." color="..."}`:

```mdc
::note
Informational note.
::

::tip
A helpful tip.
::

::warning
Something to watch out for.
::

::caution
A critical warning.
::
```

Each shorthand renders `::callout` with its matching `color` and icon. Without [Nuxt UI](https://ui.nuxt.com), use `::callout{...}` or register your own callout components.

## Binding and data passing

Comark supports `{{ }}` text interpolation and runtime data through the [binding plugin](/plugins/built-in/binding) and [data binding](/syntax/components#data-binding). Three parts work differently from MDC:

1. **Opt-in plugin and component.** Register the `binding()` parser plugin and pass the `Binding` component to your renderer.
2. **Namespaced paths.** Prefix paths with `frontmatter.`, `data.`, `meta.`, or `props.` instead of reading bare names from a flat object.
3. **Render-time data.** Pass runtime values to the renderer's `data` prop, not to `parseMarkdown()`.

### Inline `{{ }}` interpolation

::code-group
```mdc [Before]
<!-- MDC: bare paths from parse-time `data` -->
Hello {{ user.name }}, you have {{ count }} messages.
```
```mdc [After]
<!-- Comark: qualified paths against the render context -->
Hello {{ data.user.name }}, you have {{ data.count }} messages.

<!-- Or from YAML frontmatter -->
Welcome, {{ frontmatter.user.name || guest }}.
```
::

Register the plugin and component when rendering (Nuxt example):

```vue
<script setup lang="ts">
import binding, { Binding } from '@comark/vue/plugins/binding'

const markdown = 'Hello {{ data.user.name }}, you have {{ data.count }} messages.'
</script>

<template>
  <Markdown
    :value="markdown"
    :plugins="[binding()]"
    :components="{ Binding }"
    :data="{ user: { name: 'Ada' }, count: 3 }"
  />
</template>
```

### Runtime `data` prop

::code-group
```typescript [Before]
// MDC: data merged at parse time
const result = await parseMarkdown(md, { data: { user, count } })
```
```typescript [After]
// Comark: parse without data, pass data when rendering
const document = await parseMarkdown(md, { plugins: [binding()] })

// Vue / Nuxt
// <MarkdownDocument :value="document" :data="{ user, count }" :components="{ Binding }" />
```
::

`:prefixed` component props (`:label="data.user.name"`, `:answer="frontmatter.theAnswer"`) resolve against the same context without the binding plugin. Add the plugin only when you need inline `{{ path }}` text interpolation or `::if` conditionals with the `If` component.

::tip{to="/plugins/built-in/binding"}
See the binding plugin reference for `||` fallback values, `::if` and `#else` conditionals, and framework imports.
::

## Quick reference

| Task | MDC | Comark |
|------|-----|--------|
| Install (core only) | `@nuxtjs/mdc` | `comark` |
| Install (Nuxt) | `@nuxtjs/mdc` | `@comark/vue` |
| Nuxt module | `@nuxtjs/mdc` | `@comark/vue` |
| Global plugin config | `mdc: { ... }` in `nuxt.config` | None (configured per component) |
| Reusable configured component | Not supported | `defineMarkdownComponent({ plugins, components })` |
| Reusable configured renderer | Not supported | `defineMarkdownDocumentComponent({ components })` |
| Parse | `parseMarkdown(md)` | `parseMarkdown(md)` |
| Render to Markdown | `stringifyMarkdown(body, data)` | `renderMarkdown(document)` |
| Reusable parser | `await createMarkdownParser(opts)` | `createMarkdownParser(opts)` |
| AST root | `result.body` (`MDCRoot` object) | `document.nodes` (tuple array) |
| Frontmatter | `result.data` | `document.frontmatter` |
| TOC | `result.toc` (built-in) | `document.meta.toc` (`toc` plugin) |
| Excerpt | `result.excerpt` (built-in) | `document.meta.summary` (`summary` plugin) |
| Renderer | `<MDCRenderer :body :data>` | `<MarkdownDocument :value>` |
| All-in-one | `<MDC :value>` | `<Markdown :value>` |
| Highlight | `mdc.highlight` in `nuxt.config` | `shiki()` plugin in `defineMarkdownComponent` |
| Binding `{{ var }}` | Built-in, bare paths and parse-time `data` | `binding()` and `Binding`; paths such as `data.x` or `frontmatter.x`; render-time `:data` |
| Prop data binding | Parse-time `data` and `{{ }}` | `:prop="path"`, resolved against `frontmatter`, `meta`, `data`, or `props` |
| Prose components | `components/prose/Prose*.vue`, registered by the module | `Prose*` components, registered by your app |
| Render slot | `<MDCSlot />` | `<slot />` |
| Unwrap slot | `<MDCSlot unwrap="p" />` or `<slot mdc-unwrap="p" />` | `<slot unwrap="p" />` |
| Streaming | Not supported | `streaming` prop and `autoClose` |
